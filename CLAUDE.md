## Что это
Студент технической специальности складывает сюда учебные материалы, а Claude собирает из них
конспекты в PDF, отвечает на непонятные места, готовит карточки и задачи.
Все правила процесса живут ТОЛЬКО в этом файле. Навыки и команды на него ссылаются, но не переопределяют.

## Структура
```
ClaudeStudy/
├── CLAUDE.md                ← этот файл (правила)
├── .claude/skills/…/SKILL.md ← навык-указатель; порядок сборки — в .claude/commands/конспект.md
├── .claude/commands/        ← быстрые команды (/конспект, /вопросы, ...)
├── _templates/style.css     ← единый стиль PDF (НЕ переписывать, только использовать)
├── _templates/conspect.html ← HTML-шаблон PDF
├── _tools/prep.py           ← подготовка исходников: pending / extract / status (см. «Экономия токенов»)
├── _tools/build.py          ← сборка PDF одной командой: рисунки → PDF → проверки → превью → .index.json
├── _tools/FIGURES.md        ← правила рисунков (читать только при работе с рисунками)
├── .index.json              ← реестр обработанных файлов (создаётся автоматически)
└── <предмет>/
    ├── Конспект_с_пада/     ← фото/текст лекций          (приоритет 1)
    ├── Материал_преподом/   ← выданное преподавателем    (приоритет 1)
    ├── Аудиотранскрипция/   ← расшифровки лекций          (приоритет 2)
    ├── Материал_учебника/   ← главы учебника              (приоритет 2)
    ├── вопросы.md           ← мои вопросы с маркерами [?]
    ├── _конспекты/          ← ГОТОВЫЕ PDF (только сюда)
    ├── _разборы/            ← ответы на вопросы, карточки, задачи, шпаргалки (PDF)
    └── .source/             ← служебное (пользователю не показывать):
        ├── <тема>.html      ←   исходник конспекта (из него собирается PDF)
        ├── text/<имя>.md    ←   текстовая расшифровка каждого исходника (делается один раз)
        ├── tiles/<имя>/     ←   плитки рукописных исходников для расшифровки
        └── fig/             ←   спецификации рисунков
```

## Аудитория и тон
Я сам — техническая специальность. Нужна математическая строгость, полнота, без воды и восторгов.
Структура: определения → леммы/теоремы → доказательства → примеры. Формулы в LaTeX.
Примеры конкретные — с числами и решением.

## Маркеры в моих файлах (в материалах, в конспектах-с-пада, в вопросы.md)
Claude ОБЯЗАН находить их и реагировать:
- `[?]`      — не понял это место → объяснить проще, другими словами, с примером
- `[??]`     — совсем не понял → объяснить с нуля, начиная с нужных предпосылок, минимум 2 примера
- `[!]`      — важно для экзамена → выделить в конспекте отдельным акцентным блоком, добавить в шпаргалку
- `[пример]` — сюда нужен разобранный пример
- `[док]`    — нужно полное доказательство (если в материалах его нет — взять стандартное из учебника и пометить источник)
- `[почему]` — объяснить мотивацию: зачем это понятие, где применяется
- `[связь]`  — показать, как это связано с другими темами предмета
Место, где стоит маркер, в конспекте оформляется отдельным блоком «Разбор» сразу после соответствующего фрагмента.
Ответы на вопросы из `вопросы.md` идут в `_разборы/`, а не в конспект.

## Железные правила вывода
1. Единственный формат готового результата — PDF. Кладётся в `_конспекты/` или `_разборы/`.
2. Никогда не показывать план и не спрашивать подтверждение. Делать сразу и целиком.
3. Markdown/HTML — только служебно, в `<предмет>/.source/`. Пользователю не упоминать.
4. Имена файлов конспектов: `<лекция|семинар>_<ГГГГ-ММ-ДД>_<тема>.pdf`, где дата — дата самой
   лекции/семинара (не дата обработки), а `лекция`/`семинар` берётся из приоритетного источника
   (Конспект_с_пада / Материал_преподом). Если материал сборный (несколько лекций/семинаров) —
   брать дату последнего из вошедших источников.
   Остальные файлы: `разбор_<тема>_<дата>.pdf`, `карточки_<тема>_<дата>.pdf`,
   `задачи_<тема>_<дата>.pdf`, `шпаргалка_<предмет>_<дата>.pdf`.
5. Стиль PDF — всегда из `_templates/style.css` через `_templates/conspect.html`. CSS не сочинять заново.
6. Материал < ~500 слов → конспект не делать, одной строкой сказать, чего не хватает.
7. Не смешивать темы разных предметов в одном файле.
8. После каждой обработки обновлять `.index.json`: какие исходники → какой PDF, дата. При следующем запуске сканировать только то, чего нет в реестре.

## Точность
- Формулировки определений и теорем брать как в источнике; не «улучшать».
- Ничего не выдумывать. Нет доказательства в материалах и нет уверенности в стандартном — написать «доказательство не приведено в материалах».
- Расхождения между источниками отмечать явно; приоритет: лекция = материал преподавателя > учебник > аудио.

## Рисунки и графики
- Оригинал не вставлять как есть. Понять, что изображено, и пересоздать чистый SVG (оси, подписи, пропорции).
- Иллюстрация без математического содержания (фото доски целиком) — оставить оригинал.
- Не уверен, что понял график — вставить оригинал с пометкой [требует проверки].
- Графики функций и схемы — только через `_tools/figures.py`. Подробные правила (что рисовать, `--check`, визуальная
  проверка) — в `_tools/FIGURES.md`; прочитать перед созданием или правкой рисунков.

## Экономия токенов
Самое дорогое — картинки и длинный контекст: каждая картинка или большой файл в диалоге перечитывается на каждом
следующем шаге. Поэтому:
1. **Исходник смотрится глазами один раз.** Список нового — `python3 _tools/prep.py pending [предмет]`.
   Для исходника без расшифровки — `python3 _tools/prep.py extract <файл>`:
   - текстовый PDF / .txt / .docx → сразу `.source/text/<имя>.md` (без картинок);
   - рукопись (Freeform, Notes, .pages, фото) → плитки в `.source/tiles/<имя>/`. Плитки расшифровывает **субагент**
     (Agent, `model: sonnet`): читает плитки по порядку и пишет `.source/text/<имя>.md` — весь текст и формулы в LaTeX,
     маркеры `[?]`/`[!]`/… на своих местах, рисунки — словесным описанием с пометкой `[рис: …]`, неразборчивое —
     `[неразборчиво]`. В основной диалог возвращает только путь к файлу и 2–3 строки о содержании.
     Несколько исходников — несколько субагентов **в одном сообщении и с `run_in_background: false`**: основной
     диалог дождётся всех сразу (один шаг вместо пробуждения на каждого субагента).
2. **Дальше работать только с текстом.** /конспект, /сверка, /вопросы читают `.source/text/*.md`, а не PDF и не плитки.
   К оригиналу возвращаться точечно (одна плитка), только если в расшифровке `[неразборчиво]` или сомнение в формуле.
3. **Большие тексты (учебник, > ~30 тыс. символов) не читать целиком:** `grep -n` по ключевым словам темы →
   читать только найденные диапазоны строк.
4. **Готовые конспекты читать как `.source/<тема>.html`**, никогда как PDF или PNG (/карточки, /шпаргалка, /задачи,
   /объясни, /вопросы).
5. **Правки — точечно** инструментом Edit, а не перезапись всего HTML и не `sed -i` (на macOS у `sed` другой синтаксис —
   лишняя попытка = лишний шаг).
6. **Любой PDF собирается одной командой** `python3 _tools/build.py …` (рисунки, печать, проверки, превью страниц
   с рисунками, реестр). Не собирать вручную по шагам: каждый лишний шаг заново перечитывает весь диалог.
7. Не перечитывать файлы, уже отмеченные в `.index.json`; не генерировать промежуточные версии «на посмотреть».
8. Одна тема — один проход: расшифровка → HTML по шаблону → PDF. Отчёты в чат — коротко, без пересказа.
