# Рисунки в конспектах — правила

Читать перед созданием или правкой рисунков (/конспект, /переделай, /сверка). Общие правила — в `CLAUDE.md`.

## Графики функций — только вычисленные
- График функции НИКОГДА не рисовать от руки (кривые Безье, «на глаз»). Только `_tools/figures.py` (тип `plot`):
  кривая строится по вычисленным точкам $f(x)$, ветви сами рвутся в точках разрыва/полюсах.
- Для каждого графика: асимптоты (пунктир), выколотые точки (`open`), характерные точки с подписями, `equal: true`,
  если важны пропорции (гипербола, окружность, $y=x$).
- Перед вставкой — `figures.py spec.json --check`: сверить ветви, монотонность, знаки и значения с математикой
  (для $1/x$: 2 ветви, обе убывают, $y<0$ при $x<0$, $y>0$ при $x>0$). Не сходится — чинить спецификацию, не рисунок.

## Рисунки из лекций и семинаров переносятся все
Каждый `[рис N]` из расшифровок исходников становится рисунком конспекта рядом с тем объяснением, которое он
иллюстрирует, — по черновику из `.source/text/<имя>.fig.json` (проверить `--check`, поправить). Цветовые и
графические смыслы с доски (знаки площадей, направление обхода, схема перемножения) сохраняются в рисунке и
проговариваются в подписи. `type: "crop"` или сомнение в черновике — посмотреть одну указанную плитку и перерисовать;
не получается — вставить фрагмент оригинала с пометкой [требует проверки]. `build.py` предупредит, если рисунков
в конспекте меньше, чем в исходниках.

## Визуализация обязательна (текст не сокращается — рисунки ДОБАВЛЯЮТСЯ)
Каждое понятие, у которого есть геометрический/схематичный смысл, получает рисунок рядом с определением или примером.
Минимум — один рисунок на каждый раздел `h2`. Что рисовать:
| Что в тексте | Рисунок (тип в `figures.py`) |
|---|---|
| функция, пример $f(x)=\dots$, свойство функции (монотонность, ограниченность, чётность) | `plot` |
| операции над множествами, законы де Моргана, включения | `venn` (закрасить результат; для тождества — две диаграммы: левая и правая часть) |
| отображение, инъекция/сюръекция/биекция, композиция, обратное | `mapping` (для контрпримера — отдельная схема) |
| промежутки, окрестности, грани, неравенства, решение неравенства | `numberline` |
| последовательность, предел, $\varepsilon$–$N$, подпоследовательности | `sequence` (полоса $a\pm\varepsilon$, отметка $N(\varepsilon)$) |
| ход доказательства, цепочка эквивалентностей, связи понятий | `flow` |
| векторы, многоугольники, площади, определители, комплексные числа на плоскости | `geom` (`polygons`, `vectors`, `segments`, `circles`, `points`; `--check` печатает площади, длины и $\det$ — сверить с текстом) |
Подпись рисунка — полное предложение: что изображено и какой вывод из рисунка следует.
В HTML знак `<` внутри формул писать как `\lt` (иначе `$A<B$` браузер читает как тег `<B>` и вёрстка ломается).
Ручной SVG и одноразовые генераторы — только если ни один тип не подходит (сначала проверить `geom`).
Исходник: `<!--fig:id-->` в `.source/<тема>.html` + `.source/fig/<тема>.json`; ручные SVG (прямые и окружности) —
`.source/fig/<тема>/<имя>.svg` + метка `<!--svg:имя-->`. Сборка и подстановка — только `_tools/build.py` (см. `/конспект`, шаг 6).

Формат спецификации всех типов — в docstring `_tools/figures.py` (первые ~35 строк); остальной код не читать.

## Визуальная проверка
`build.py` сам рендерит страницы с подписями «Рис.» (60 dpi) в `.source/_preview/` и печатает пути. Посмотреть только их.
Проверить: график совпадает с `--check`, подписи не налезают, рисунок не разрезан страницей.
